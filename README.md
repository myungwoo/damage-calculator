# 🗡️ 메이플랜드 데미지 계산기

메이플랜드 나이트로드(표창)용 데미지 · 방컷 확률 계산기.

**👉 <https://myungwoo.github.io/damage-calculator/>** — 설치 없이 브라우저에서 바로 돌아간다.

## ✨ 특징

- 📊 **정확한 방컷 확률** — 근사나 시뮬레이션이 아니라 FFT 컨볼루션으로 확률분포를 직접 계산한다
- ☠️ **베놈 도트 데미지 반영** — 중첩 규칙과 1초 틱까지 원작 유출 코드 기준으로 모델링했다
- 🎲 **트리플 스로우 난수 순환** — 라인 간 상관까지 실측으로 확정해서 넣었다
- 🐌 **몬스터 프리셋 417종** — 원작 Mob.wz(GMS v83) 기준 정확도 · 공격력 · 넉백 · 속성 · 보스 여부 포함.
  혼테일 파트 10종, 뉴리프시티 · 크림슨우드, 핑크빈(미출시)까지 들어 있다
- 💨 **넉백 확률** — 시전 1회에 타격 하나라도 몹의 넉백 수치를 넘길 확률을 계산한다.
  자쿰처럼 자리에 고정된 몹(52종)은 수치와 무관하게 "넉백 불가"로 갈라 준다
- 🛡️ **회피 확률** — 몹 공격을 흘릴 확률을 원작 유출 코드의 물리 / 마법 판정 그대로 계산한다.
  페이크(쉐도우 쉬프터)와 회피율 1당 증가폭까지 같이 보여준다
- 💥 **피격 데미지** — 흘리지 못했을 때 들어오는 데미지를 **몸박 · 물리 공격 · 마법 공격**
  으로 나눠 계산한다. 공격력이 다른 공격은 각각 한 줄씩, 몹 공격업 1 / 2단계와
  방어력 1당 감소폭까지 보여준다
- 🛡️ **몹 방어업 반영** — "N방부터 방어업이 걸렸다면" 방컷 확률이 어떻게 되는지 계산한다
- 🧟 **몹 스킬 표시** — 공격업 · 방어업 · 물리 무효 · 회복 같은 스킬을 칩으로 보여주고,
  소환하는 몹까지 적는다. 방컷 확률을 나쁘게 만드는 스킬은 결과에도 경고로 띄운다
- 🖼️ **몬스터 그림** — 원하는 순간에만 펼쳐서 어떤 몹인지 확인한다
- 📌 **결과 패널 고정** — 입력을 만지는 동안 데미지와 방컷 확률이 계속 보인다
- 📈 **방컷 확률 막대 그래프** — 각 방 확률과 누적 확률을 겹쳐 그려서 분포가 한눈에 들어온다
- 🎚️ **스킬 레벨 슬라이더** — 슬라이더 · 직접 입력 · M(만렙) 버튼을 함께 제공한다
- 📱 모바일에서는 결과가 하단 시트로 접힌다
- 🌗 다크 / 라이트 모드
- 💾 저장 슬롯 3개 (localStorage)

## 🎯 정확도

이 계산기의 목표는 "대충 맞는 평균"이 아니라 **원작 서버가 실제로 굴리는 난수를 그대로 재현하는 것**이다.
아래는 그러려고 실제로 한 일들이다.

### 1. 확률을 세지 않고 계산한다

몬테카를로 시뮬레이션은 돌린 횟수만큼만 정확하고, 돌릴 때마다 값이 흔들린다.
이 계산기는 데미지 한 라인의 확률분포를 닫힌 식으로 만든 다음 FFT 컨볼루션으로
N방까지 누적해서 방컷 확률을 **직접** 구한다.
같은 입력이면 항상 같은 값이 나오고, 오차는 표본 수가 아니라 부동소수점 정밀도가 정한다.

### 2. 원작 구현을 뜯어보고 고친 것들

흔히 넘어가는 지점들이다. 괄호 안은 **그냥 넘어갔을 때 실제로 벌어졌던 오차**다.

| 짚어낸 것 | 무시했다면 |
| --- | --- |
| 라인 데미지는 균등분포가 아니라 **사다리꼴**이다 (스탯 롤 − 방어 롤) | 방어력 난수 폭 비율에 따라 방컷 확률이 최대 **36.4%p** 어긋남 |
| 하한 1에 눌린 구간은 한 점에 뭉친 **확률질량**이다 | 평균 데미지 **1.14배** 과대평가, 방컷 확률 최대 **98%p** |
| 본체가 하한 1에 눌리면 **쉐도우 파트너 타격도 0이 아니라 1**이다 | 그 구간의 타격당 데미지가 절반, 방컷 확률 **0.4%p** |
| 크리티컬 라인은 매끈한 배율이 아니라 **계단**이다 (가산항은 스킬% 적용 전 정수에 곱한다) | 닿지 않는 정수 데미지를 놓쳐 크리티컬 최댓값이 **1~2 높게** 나옴 |
| 트리플 스로우 3라인은 **서로 독립이 아니다** (원작의 7칸 난수 순환) | 시전 1회 표준편차가 15% 어긋나 방컷 확률이 **1.6~3.5%p** 이동 |
| 베놈은 커뮤니티 근사식이 아니라 **유출 코드의 원식**으로 계산한다 | 평균만 맞고 분포가 틀림 |
| 베놈 틱 수는 지속시간이 아니라 **지속시간 + 1**이다 (부여 딜레이 때문) | 만렙 기준 틱 하나(20%)를 통째로 누락 |

근거가 되는 유출 코드 위치와 계산식은 전부 [`CLAUDE.md`](CLAUDE.md)에 정리해 뒀다.

### 3. 코드로 알 수 없는 건 실측했다

- **난수 순환의 라인 간 결합**: 메이플랜드에서 트리플 스로우 40시전을 기록해
  관측 가능한 9개 짝을 전수로 대조했다. 8개는 15~23건씩 반례가 나왔고
  **딱 하나만 40/40으로 살아남았다.** 쉐도우 파트너 ON/OFF와 무관한 것도 확인했다.
- **베놈 틱 1회 30000 상한**: 원작 유출 코드에는 **없는** 제한인데 메이플랜드에는 있다.
- **첫 틱은 부여 정확히 1초 뒤**이고, 중첩에 성공하면 틱 타이머가 초기화된다.
  트리플 스로우 0.6초 주기라면 첫 틱이 두 번째 공격 뒤에 떨어진다.

### 4. 매번 검증한다

- 방컷 확률과 베놈은 **배포 코드와 독립적으로 작성한 참조 DP**, 그리고
  **원작 엔진을 그대로 옮긴 몬테카를로**와 대조한다.
- 방컷 확률 최대 오차 **0.03%p 이하** (HP 축소 · 샤프 아이즈 포함, 어느 조건에서도).
- 베놈 누적 데미지 분포: 400만 회 몬테카를로 대비 **0.01%p**.
- 회피 확률도 원작 판정을 한 줄씩 옮긴 몬테카를로와 대조한다 (레벨 페널티 · 클램프 · 몹 명중률 0 포함).
- 피격 데미지도 원작 `PDamage` / `MDamage`를 한 줄씩 옮긴 참조 구현과 대조한다.
- 넉백 확률도 원작 라인 판정을 그대로 옮긴 몬테카를로와 대조한다 (200만 회 대비 **0.05%p**).
- 유닛 테스트 173개가 **모든 PR과 모든 배포에서** 자동으로 돌아간다.

### 5. 남아 있는 오차 (숨기지 않는다)

| 항목 | 영향 |
| --- | --- |
| 명중률은 커뮤니티 근사식을 쓴다 (원작은 1/ACC에 선형) | 명중률 100%면 동일, 애매한 구간에서 최대 45%p |
| HP가 16383을 넘으면 눈금을 축소해 계산 | 0.1%p 이하 |
| 럭키 세븐의 타격 간 결합은 미측정 | 현재는 독립으로 둔다 |
| 회피 확률은 실측 없이 유출 코드만 따랐다 | 회피는 성공 / 실패만 보여서 역산할 수단이 없다 |
| 페이크는 클라이언트가 굴려서 회피와의 판정 순서를 모른다 | 총 확률은 순서와 무관하게 `1 − (1 − 회피)(1 − 페이크)`로 같다 |
| 어느 공격이 얼마나 자주 나오는지는 모른다 | 공격력이 다른 공격을 전부 보여줄 뿐, 빈도는 반영하지 않는다 |
| 피격 데미지도 아직 실측 대조를 안 했다 | 다만 화면에 숫자가 뜨는 값이라 회피와 달리 검증할 수 있다 |
| 어느 몹이 공격업을 쓰는지는 프리셋에 없다 (몹 스킬 목록 미수집) | 몹과 무관하게 1 / 2단계 값을 같이 보여준다 |
| 넉백도 클라이언트가 판정해서 유출 서버 코드에 식이 없다 | "타격 하나가 넉백 수치를 넘기면 밀린다"를 기준으로 잡았다. 이동 불가 몹은 이동 능력(원작 MoveAbility)으로 갈랐다 |

## 🤖 CI

검사 목록은 [`ci.yml`](.github/workflows/ci.yml) 한 곳에만 적혀 있고,
배포 워크플로우가 같은 파일을 재사용한다. PR과 배포가 서로 다른 기준으로 통과하는 일이 없다.

| 시점 | 하는 일 |
| --- | --- |
| PR | 포맷 검사 → 린트 → 타입 검사 → 테스트 → 빌드 |
| `main` 푸시 | 같은 검사를 통과한 뒤에만 GitHub Pages로 배포 |

포맷 규칙은 `.prettierrc.json` 하나가 단일 출처다. ESLint의 `prettier/prettier` 규칙도
같은 파일을 읽으므로 `npm run format`과 `npm run lint`가 어긋나지 않는다.
손으로 표와 줄바꿈을 맞춘 문서(`*.md`)는 `.prettierignore`로 검사에서 뺐다.

## ☠️ 베놈에 대해

베놈은 데미지 라인이 아니라 몬스터 HP를 직접 깎는 스킬이라 계산 방식이 다르다.

- 몹 방어력 · 크리티컬 · 스킬 데미지%의 영향을 **받지 않는다**
- 타격마다 발동 판정을 굴리므로 **쉐도우 파트너가 발동 기회를 2배로** 만든다
- 이 데미지만으로는 몬스터를 **잡을 수 없다** (HP 1에서 멈춘다)
- 틱 1회 데미지는 **30000에서 잘린다** (메이플랜드 고유 사양, 원작에는 없는 제한)
- 보스 · 독 무효 · 독 반감 몬스터에는 걸리지 않는다
- 1초마다 틱이 들어가서 같은 방수라도 공격 속도에 따라 결과가 달라진다.
  베놈을 켜면 **분당 공격 횟수** 입력이 나타난다 (트리플 스로우 기준 100회/분)

일부 세부 동작(빗나간 타격의 발동 판정 등)은 실측이 어려워 가정을 두고 계산한다.
자세한 근거와 가정은 [`CLAUDE.md`](CLAUDE.md)에 정리했다.

## ⚠️ 호환성

몬스터 프리셋의 `id`를 원작 Mob.wz 몹 ID로 바꿨다.
저장 데이터에는 몬스터 id가 아니라 수치가 들어가므로 기존 저장 슬롯은 그대로 열린다.
저장 데이터에 없는 항목만 기본값으로 채워진다 — 베놈(사용 안 함), 추가 INT와 방어력(0),
몹 공격력(프리셋 값).
